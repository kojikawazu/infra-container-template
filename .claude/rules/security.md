# セキュリティ

本テンプレは**ローカル開発・検証用**。詳細な仕様は [docs/06-security-specification.md](../../docs/06-security-specification.md) を正とし、本ルールは変更時に必ず守る判断基準を定める。

## ポート公開範囲

- **ホストポートは `127.0.0.1` バインドを既定とする**（例: `127.0.0.1:5432:5432`）。新しいサービスを追加する際もこの形式に揃える。
- `0.0.0.0` バインドへ変更する場合は、**理由を PR 説明に明記**し、docs/06-security-specification.md を同一 PR で更新する。無言で公開範囲を広げない。

## シークレット管理

- 認証情報・接続情報は `.env` に置く。`.env` は Git 管理外（`.gitignore` で `.env*` を除外、`.env.example` のみ例外）。
- **`.env.example` に実在の認証情報を書かない**。既知のダミー値（例: `admin`/`admin`）のみを置く。
- シークレット・鍵ファイル（`*.pem` / `*.key` 等）・大容量バイナリをコミットしない。
- 環境変数を追加・変更・削除したら `.env.example` を同一 PR で更新する（[documentation.md](documentation.md) の影響マップ）。

## コンテナ権限

- **`docker.sock` のマウントは既定で無効にする**。マウントはコンテナからホストの Docker を操作可能にする（実質ホスト権限）ため、必要な機能に限り opt-in とし、リスクをコメントで明記する。
- `privileged: true`・ホストネットワーク・ホストパスの書き込みマウントを既定で使わない。使う場合は理由を PR 説明に明記する。
- `user: root` での実行は、named volume の権限確保など明確な理由がある場合に限る。

## イメージ

- イメージはバージョンタグでピン留めする（`latest` を使わない）。再現性を確保し、意図しない更新による破壊と既知脆弱性の混入を防ぐ。

## 開発用の緩和を締め直す

- 認証無効化・PLAINTEXT 通信など「開発容易性のための緩和」を新たに入れる場合は、**docs/06-security-specification.md に緩和内容と本番での締め直し方をセットで記載する**。緩和だけを入れて記録を残さない状態を作らない。
