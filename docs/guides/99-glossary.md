# 用語集（学習用）

各ガイドに横断的に出てくる用語を、**このテンプレのどこに出てくるか**とセットでまとめた逆引き集。
「ガイドを読んでいて知らない語が出てきた」ときの参照先として使う。

- 詳しい使い方は各サービスのガイド（[ガイド一覧](./00-index.md)）を参照する。
- ここでは語の意味と、テンプレ内での現れ方だけを扱う。

---

## 1. Docker / Compose の基礎

| 用語 | 意味 | このテンプレでの現れ方 |
|------|------|----------------------|
| **イメージ（image）** | コンテナの実行に必要なファイル一式を固めた読み取り専用のテンプレート。 | 各 compose.yaml の `image:`。必ずバージョンタグでピン留めし、`latest` は使わない（再現性の確保）。 |
| **コンテナ（container）** | イメージを起動した実行中のプロセス。イメージ 1 つから複数起動できる。 | `docker compose ps` で一覧できる。 |
| **タグ（tag）** | イメージのバージョン識別子（`postgres:16.4` の `16.4`）。 | `latest` は中身が黙って変わるため使用禁止。 |
| **サービス（service）** | Compose が管理するコンテナの定義単位。サービス名は同一ネットワーク内の**ホスト名**にもなる。 | `postgres`, `kafka`, `grafana` など。コンテナ間接続は `postgres:5432` のようにサービス名で行う。 |
| **profile** | Compose の起動対象を絞る仕組み。profile を指定しない限り、その定義は起動しない。 | 本テンプレは profile 未指定では何も起動しない設計。`docker compose --profile postgres up -d` / `make up p=postgres`。`sql` / `nosql` / `messaging` / `monitoring` / `search` / `emulator` / `all` のまとめ起動もある。 |
| **ネットワーク（network）** | コンテナ同士が通信する仮想 LAN。同一ネットワーク内ではサービス名で名前解決できる。 | 共通ネットワーク `infra-net`。⚠ コンテナ内から `localhost` を指定すると「自分自身」を指すため接続できない（最頻出のミス）。 |
| **ポートマッピング** | ホストのポートをコンテナのポートへ転送する設定（`127.0.0.1:5432:5432`）。 | 左が**ホスト側**、右が**コンテナ側**。ホスト PC からは `localhost:<ホスト側ポート>` で接続する。 |
| **バインドアドレス** | ポートを公開する範囲。`127.0.0.1` は自ホストのみ、`0.0.0.0` は同一 LAN からも到達可能。 | 既定は `127.0.0.1` バインド。広げる場合は理由を PR に明記し [06 セキュリティ仕様書](../06-security-specification.md) を同一 PR で更新する。 |
| **ボリューム（volume）** | コンテナの外側にデータを永続化する仕組み。コンテナを消してもデータは残る。 | 各 DB のデータ領域。`docker compose down` ではデータは残り、`down -v` で削除される。 |
| **named volume** | Docker が管理する名前付きボリューム（ホスト上の実体パスを意識しない）。 | 本テンプレの永続化は基本的にこちら。権限問題を避けるため `user: root` が必要になる場合がある。 |
| **bind mount** | ホストの特定ディレクトリをコンテナに直接マウントする方式。 | 設定ファイル（`prometheus.yml`, `datasource.yml` など）の読み込みに使う。書き込みマウントは既定で使わない。 |
| **healthcheck** | コンテナが「起動した」だけでなく「使える状態か」を定期コマンドで判定する設定。 | DB 系で定義。`depends_on: condition: service_healthy` と組み合わせ、依存側の起動順を制御する。 |
| **depends_on** | サービスの起動順の依存関係。既定では「起動した」までしか待たない。 | 「接続できるまで待つ」には healthcheck との併用が必要。 |
| **環境変数 / `.env`** | コンテナへ設定値を渡す仕組み。Compose は同ディレクトリの `.env` を自動読み込みする。 | 初回に `cp .env.example .env`。`.env` は Git 管理外、`.env.example` にはダミー値のみ置く。 |
| **エントリポイント / コマンド** | コンテナ起動時に実行されるプロセス。これが終了するとコンテナも終了する。 | `command:` で設定ファイルのパスを渡すサービスがある（Loki / Tempo など）。 |
| **docker.sock マウント** | ホストの Docker API をコンテナへ渡すマウント。実質ホスト権限に相当する。 | 既定で無効。必要な機能に限り opt-in とし、リスクをコメントで明記する。 |

## 2. インフラ / 運用の一般用語

| 用語 | 意味 | 補足 |
|------|------|------|
| **永続化（persistence）** | プロセスやコンテナが停止してもデータが失われないようにすること。 | ボリュームの有無がそのまま永続化の有無になる。 |
| **ステートフル / ステートレス** | 自身が状態（データ）を持つか否か。 | DB・Kafka はステートフル、Grafana の描画処理などは比較的ステートレス。ボリューム設計の判断軸。 |
| **冪等性（idempotency）** | 同じ操作を何度実行しても結果が変わらない性質。 | `up -d` の再実行や、メッセージの再配信（at-least-once）を扱う際の前提になる。 |
| **可観測性（observability）** | 外部から観測できる情報だけで内部状態を説明できる度合い。 | 3 本柱＝**メトリクス / ログ / トレース**。本テンプレでは Prometheus / Loki / Tempo が対応し、Grafana で束ねて見る。 |
| **メトリクス（metrics）** | 数値の時系列データ（CPU 使用率、リクエスト数など）。 | Prometheus が収集。集計に強く、個別の事象は追えない。 |
| **ログ（logs）** | 発生した事象のテキスト記録。 | Loki が集約。事象の詳細は分かるが集計は苦手。 |
| **分散トレース（tracing）** | 1 リクエストが複数サービスを渡り歩く経路と所要時間の記録。 | Tempo が保存。どこが遅いかの特定に使う。 |
| **時系列データベース（TSDB）** | 時刻付き数値の保存・集計に特化した DB。 | Prometheus の内部ストレージ。 |
| **エージェント / エクスポーター** | 監視対象の情報を監視システムが読める形で公開するコンポーネント。 | Prometheus は「公開された HTTP エンドポイントを取りに行く」方式（[16 Prometheus](./16-prometheus.md)）。 |
| **プル型 / プッシュ型** | 監視側が取りに行くか、被監視側が送りつけるか。 | Prometheus はプル型、Loki / Tempo への送信はプッシュ型。 |
| **シークレット（secret）** | 認証情報・鍵など漏洩してはいけない値。 | `.env` に置き Git にコミットしない。`*.pem` / `*.key` も同様（[06 セキュリティ仕様書](../06-security-specification.md)）。 |
| **エミュレータ / 互換実装** | 本番サービスの API を模した、ローカルで動く代替実装。 | DynamoDB Local・BigQuery emulator・LocalStack・MinIO（S3 互換）。API は似ているが挙動が完全一致するとは限らない。 |
| **開発用の緩和** | 認証無効化・平文通信など、開発を楽にするための意図的な妥協。 | 入れる場合は「緩和内容」と「本番での締め直し方」をセットで [06 セキュリティ仕様書](../06-security-specification.md) に記録する。 |

## 3. サービス固有の用語

### RDB / NoSQL / KVS

| 用語 | 意味 | 関連ガイド |
|------|------|-----------|
| **RDB（リレーショナルDB）** | 表とスキーマ、SQL で扱う DB。 | [01 PostgreSQL](./01-postgres.md) / [02 MySQL](./02-mysql.md) / [03 MariaDB](./03-mariadb.md) / [04 MSSQL](./04-mssql.md) |
| **スキーマ / マイグレーション** | テーブル定義と、その定義変更を段階的に適用する仕組み。 | RDB 全般 |
| **Adminer** | ブラウザから複数 RDB を操作できる軽量 Web クライアント。 | `:8080` で共有（SQL 系 profile） |
| **ドキュメント指向 DB** | JSON 状の文書を単位に格納する NoSQL。スキーマが緩い。 | [06 MongoDB](./06-mongodb.md) |
| **コレクション / ドキュメント** | MongoDB における「テーブル / 行」に相当する概念。 | [06 MongoDB](./06-mongodb.md) |
| **KVS（Key-Value Store）** | キーに値を対応づけるだけの単純・高速な DB。 | [08 Redis](./08-redis.md) |
| **TTL（Time To Live）** | データの生存期間。期限が来ると自動削除される。 | キャッシュ設計の基本（Redis） |
| **パーティションキー / ソートキー** | DynamoDB で項目の配置先と並び順を決めるキー。 | [07 DynamoDB Local](./07-dynamodb.md) |
| **ベクトル検索 / 埋め込み（embedding）** | テキスト等を数値ベクトル化し、意味的な近さで検索する方式。 | [05 pgvector](./05-pgvector.md) |
| **RAG** | 外部データを検索して LLM の回答に与える構成。ベクトル検索が土台になる。 | [05 pgvector](./05-pgvector.md) / [05 データ仕様書](../05-data-specification.md) |
| **拡張（extension）** | PostgreSQL に機能を追加する仕組み。`CREATE EXTENSION` で有効化する。 | pgvector は拡張として導入される |

### ストレージ / メッセージング / メール

| 用語 | 意味 | 関連ガイド |
|------|------|-----------|
| **オブジェクトストレージ** | ファイルを「オブジェクト」としてフラットに保存するストレージ。 | [09 MinIO](./09-minio.md) |
| **バケット（bucket）** | オブジェクトを入れる名前空間。S3 系の最上位の入れ物。 | [09 MinIO](./09-minio.md) / [15 LocalStack](./15-localstack.md) |
| **S3 互換 API** | Amazon S3 と同じ API 仕様を実装していること。SDK をほぼそのまま使える。 | MinIO / LocalStack |
| **メッセージキュー** | 送信側と受信側を非同期に切り離す仲介。 | [11 RabbitMQ](./11-rabbitmq.md) |
| **イベントストリーミング** | イベントをログとして永続化し、複数の購読者が任意の位置から読める方式。 | [10 Kafka](./10-kafka.md) |
| **トピック / パーティション** | Kafka のメッセージ分類単位と、その並列分割単位。 | [10 Kafka](./10-kafka.md) |
| **オフセット（offset）** | パーティション内の読み取り位置。消費者側が保持する。 | [10 Kafka](./10-kafka.md) |
| **プロデューサ / コンシューマ** | メッセージの送信側 / 受信側。 | Kafka / RabbitMQ |
| **コンシューマグループ** | 複数コンシューマで負荷分散しつつ、重複なく処理する単位。 | [10 Kafka](./10-kafka.md) |
| **ブローカー（broker）** | メッセージを中継・保持するサーバ本体。 | Kafka / RabbitMQ |
| **リスナー / advertised listener** | Kafka が「自分への接続先」としてクライアントに知らせるアドレス。 | ホストからは `9092`、コンテナ間は `kafka:19092`。接続失敗の主因になりやすい（[10 Kafka](./10-kafka.md)） |
| **AMQP** | RabbitMQ が使うメッセージングのプロトコル。 | [11 RabbitMQ](./11-rabbitmq.md) |
| **exchange / queue / binding** | RabbitMQ の配送先決定（exchange）、蓄積先（queue）、両者の紐付け（binding）。 | [11 RabbitMQ](./11-rabbitmq.md) |
| **SMTP** | メール送信のプロトコル。 | [12 Mailpit](./12-mailpit.md) |
| **メールキャッチャー** | 送信メールを実際には配送せず受け止めて表示する開発用ツール。 | Mailpit（SMTP `:1025` / UI `:8025`） |

### 検索 / 監視

| 用語 | 意味 | 関連ガイド |
|------|------|-----------|
| **全文検索** | 文書本文を対象に、単語単位の索引で検索する方式。 | [13 OpenSearch](./13-opensearch.md) |
| **インデックス（検索）** | 検索対象の文書群と、その転置索引。RDB のインデックスとは別概念。 | [13 OpenSearch](./13-opensearch.md) |
| **アナライザ / トークナイズ** | 文章を検索単位（トークン）に分割する処理。日本語では特に重要。 | [13 OpenSearch](./13-opensearch.md) |
| **ES 互換** | Elasticsearch の API 仕様と互換であること。 | OpenSearch |
| **スクレイプ（scrape）** | Prometheus が対象の `/metrics` を定期取得すること。 | [16 Prometheus](./16-prometheus.md) |
| **scrape interval / target / job** | 取得間隔、取得先、取得先のまとまり。`prometheus.yml` で定義する。 | [16 Prometheus](./16-prometheus.md) |
| **PromQL** | Prometheus のクエリ言語。 | [16 Prometheus](./16-prometheus.md) |
| **データソース（datasource）** | Grafana が参照する取得元（Prometheus / Loki / Tempo など）。 | [17 Grafana](./17-grafana.md) |
| **プロビジョニング** | ダッシュボードやデータソースを設定ファイルから自動投入すること。 | `datasource.yml`（[17 Grafana](./17-grafana.md)） |
| **ラベル（label）** | 時系列やログストリームを識別するキー・バリュー。 | 種類を増やしすぎると系列数が爆発する（Prometheus / Loki） |
| **LogQL** | Loki のログ検索クエリ言語。PromQL に似た記法。 | [18 Loki](./18-loki.md) |
| **スパン（span）／トレース ID** | トレースを構成する 1 区間と、リクエスト全体を束ねる ID。 | [19 Tempo](./19-tempo.md) |
| **OTLP** | OpenTelemetry の標準送信プロトコル。gRPC `:4317` / HTTP `:4318`。 | [19 Tempo](./19-tempo.md) |
| **OpenTelemetry (OTel)** | メトリクス・ログ・トレースの収集仕様と SDK の標準規格。 | [19 Tempo](./19-tempo.md) |
