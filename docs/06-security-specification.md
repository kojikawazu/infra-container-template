# 06. セキュリティ仕様書

認証・認可・暗号化・脆弱性対策を定義する。

> 本テンプレは**ローカル開発・検証用**。本番運用ではここに記載した「開発用の緩和」を必ず締め直すこと。

## ネットワーク公開範囲（最重要）

- **全サービスのホストポートは `127.0.0.1` バインド**（例: `127.0.0.1:5432:5432`）。
  - `localhost` からの接続性は変わらず、**同一LAN上の他端末からはアクセス不可**。
  - 開発機をカフェ・社内LAN等の共有ネットワークに繋いだ際の意図しない公開を防ぐ。
  - 外部からアクセスさせたい場合のみ、当該サービスのポートを明示的に `0.0.0.0` バインドへ変更する。

## 認証

- 各ミドルウェアの認証情報は `.env`（`.env.example` をコピー）で集中管理。`.env` は Git 管理外。
- `.env.example` の値は**既知のダミー**（例: `admin`/`admin`）。loopback バインドで露出面を絞った上での開発用デフォルトであり、**LAN/公開環境で使う場合は必ず変更する**。

## 認可

- ローカル検証用のため、各サービスは管理者相当の単一アカウントのみを想定（ロール分離なし）。

## 暗号化・機密情報管理

- ローカル開発のため通信は基本 PLAINTEXT（TLS なし）。loopback バインドで通信経路をホスト内に閉じる。
- **OpenSearch**: 開発容易性のためセキュリティプラグインを無効化（HTTP・認証なし）。本番では TLS + 認証を必須化すること。
- **Kafka**: 開発用に PLAINTEXT リスナー。LAN へ公開する場合は SASL_PLAINTEXT 等で認証を付与する。
- シークレット・鍵ファイル・大容量バイナリはコミットしない（`.gitignore` で `.env*` を除外）。

## 脆弱性対策

- **LocalStack の `docker.sock` マウントは既定で無効**。マウントするとコンテナからホストの Docker を操作できる（実質ホスト権限＝コンテナエスケープ/ホストRCE 相当）ため、Lambda 実行が必要なときだけ opt-in する。
- **DynamoDB Local は `user: root`** で動作（named volume への書き込み権限確保のため）。privileged でもホストマウントでもなく、ポートは loopback のため影響は限定的。非 root 化するには volume の chown（init コンテナ等）が必要。
- イメージはバージョンタグでピン留めできるものは固定（再現性・既知脆弱性の回避）。
